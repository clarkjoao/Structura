# Design

## Context

Plugins share the host React through globals (`__REACT__`, `runtime-globals.ts`) and receive
`api.ui.CodeEditor`. Host components live in `src/components/ui` (shadcn, regenerated by the CLI,
not hand-edited) and are styled by the host's Tailwind build.

## Decisions

1. **A facade, not re-exports.** `src/features/plugins/ui-kit/` wraps the shadcn components with
   small, stable props: `Select` takes `options` instead of Radix parts, `Tabs` takes `tabs`,
   `Card` takes `title` / `description` / `footer`, `Tooltip` takes `content`. Regenerating a
   shadcn component cannot break a plugin, and the kit's surface is reviewable in one file.
   _Alternative:_ re-export shadcn — couples the plugin contract to the CLI's output.
2. **Same objects, two doors.** `api.ui` spreads the kit next to `CodeEditor`;
   `installPluginRuntimeGlobals()` also sets `window.__STRUCTURA_UI__ = PLUGIN_UI_KIT`. Bundled
   plugins externalize `@structura/ui` → `__STRUCTURA_UI__`. Both are versioned with the API.
3. **`className` and `style` pass through** on every kit component, so a plugin can lay out with
   the theme tokens; the kit itself never depends on classes the plugin writes.
4. **Typing.** `plugin.types.ts` (copied verbatim into plugins, no `@/` imports) declares each
   kit component's props and a `PluginUiKit` interface; the host facade is checked against it
   (`const PLUGIN_UI_KIT: PluginUiKit`). `plugins/*/src/types/structura-ui.d.ts` declares the
   `@structura/ui` module from `PluginUiKit`; `sync-types` copies it too.
5. **`Stack` and `Field`** are the two layout helpers, so a plugin needs no utility CSS for the
   common form: label + control + hint/error, stacked with a gap.

## Risks / Trade-offs

- [A plugin built against 1.18 runs on an older host without the global] → `apiVersion: "^1.18"`
  in its manifest makes the host refuse it, as for every API addition.
- [The kit grows into a second design system] → only components plugins already hand-roll are
  added; anything else uses theme tokens.
